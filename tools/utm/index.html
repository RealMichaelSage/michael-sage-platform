Скрипт сквозного проброса меток (Tilda / Web)

Если вы ведете платный трафик на лендинг, а целевым действием является переход в Telegram-бота, метки из адресной строки пользователя потеряются при клике по кнопке. Скрипт ниже автоматически подхватывает параметры страницы и дописывает их ко всем исходящим ссылкам на сайте.

// HTML / JAVASCRIPT ДЛЯ ВСТАВКИ В <HEAD> ИЛИ БЛОК T123 
<!-- Скрипт сквозного проброса UTM-меток (AiSAGE) -->
<script>
document.addEventListener('DOMContentLoaded', function() {
    // 1. Получаем строку запроса из URL страницы
    var queryString = window.location.search;

    // 2. Если параметры существуют, обрабатываем ссылки
    if (queryString) {
        var allLinks = document.querySelectorAll('a');
        allLinks.forEach(function(link) {
            var href = link.getAttribute('href');
            // Пропускаем якорные ссылки (#) и системные вызовы
            if (href && !href.startsWith('#') && !href.startsWith('javascript:')) {
                // Корректно объединяем через ? или &
                if (href.indexOf('?') !== -1) {
                    link.href = href + '&' + queryString.substring(1);
                } else {
                    link.href = href + queryString;
                }
            }
        });
    }
});
</script>
Как установить на Тильде за 30 секунд:
  1. Добавьте на страницу лендинга блок T123 (HTML-код) из категории «Другое».
  2. Вставьте скопированный скрипт в блок и нажмите «Сохранить и закрыть».
  3. Опубликуйте страницу. Теперь при переходе на yoursite.ru/?utm_source=yandex все ссылки на странице автоматически получат этот параметр.

Почему Telegram ограничивает параметр 64 байтами?

В протоколе Telegram Bot API команда /start [payload] жестко ограничена спецификацией: длина параметра start не может превышать 64 байта (ASCII-символов). Если попытаться передать обычную строку utm_source=yandex&utm_medium=cpc&utm_campaign=brand, ссылка моментально превысит лимит, и Telegram просто отбросит параметр. Пользователь попадет в бота, но бот получит пустой старт.

Как Telegram-бот декодирует метки на сервере

При нажатии на кнопку «Запустить» бот получает событие с текстом команды, например: /start c315YSZtPWNwYyZjPXNhbGU. Бот берет полезную нагрузку, восстанавливает URL-safe Base64 и парсит querystring.

PYTHON (AIOGRAM 3.X / TELEBOT) 
import base64
from urllib.parse import parse_qs

def decode_utm_payload(payload: str) -> dict:
    """Декодирует URL-safe Base64 payload из команды /start в Telegram боте"""
    try:
        # Восстанавливаем паддинг '=' до кратности 4
        padded = payload + '=' * (-len(payload) % 4)
        # Декодируем URL-safe Base64 (- на +, _ на /)
        raw_bytes = base64.urlsafe_b64decode(padded)
        decoded_query = raw_bytes.decode('utf-8')
        
        # Парсим параметры s, m, c, o, t, r
        parsed = parse_qs(decoded_query)
        return {
            'utm_source': parsed.get('s', [None])[0],
            'utm_medium': parsed.get('m', [None])[0],
            'utm_campaign': parsed.get('c', [None])[0],
            'utm_content': parsed.get('o', [None])[0],
            'utm_term': parsed.get('t', [None])[0],
            'referral_code': parsed.get('r', [None])[0],
        }
    except Exception as e:
        return {}

function decodeUtmPayload(payload) {
  try {
    // Восстанавливаем символы Base64 и выравнивание
    let base64 = payload.replace(/-/g, '+').replace(/_/g, '/');
    while (base64.length % 4) base64 += '=';
    
    const decoded = Buffer.from(base64, 'base64').toString('utf-8');
    const params = new URLSearchParams(decoded);

    return {
      utm_source: params.get('s'),
      utm_medium: params.get('m'),
      utm_campaign: params.get('c'),
      utm_content: params.get('o'),
      utm_term: params.get('t'),
      referral_code: params.get('r')
    };
  } catch (err) {
    return null;
  }
}

Вопросы и ответы о диплинках в Telegram

Telegram поддерживает только один параметр запуска для ботов: ?start=ПАРАМЕТР. Знаки амперсанда (&) и вопроса внутри этого значения парсер Telegram игнорирует либо ломает. Кроме того, длина параметра жестко ограничена 64 байтами. Перевод в URL-safe Base64 решает обе проблемы: убирает спецсимволы и позволяет уместить до 5–6 сокращенных параметров в один компактный токен.
Если значение после ?start= окажется длиннее 64 байт, клиент Telegram просто проигнорирует параметр. Пользователь откроет бота, нажмет кнопку «Запустить», но бот получит только команду /start без хвоста с метками. Сквозная конверсия и источник трафика будут потеряны. Именно поэтому наш счетчик выделяет превышение красным цветом.
В стандартном Base64 используются символы + и /, а в конце добавляется знак равенства = для выравнивания. В URL адресной строки символ + заменяется на пробел, а / ломает структуру пути. В URL-safe Base64 (RFC 4648) плюсы заменяются на дефисы (-), слэши на подчеркивания (_), а концевые знаки = просто обрезаются. Это гарантирует 100% стабильность ссылки в любых мессенджерах.
Да, алгоритм генератора предварительно кодирует UTF-8 символы перед упаковкой в Base64. Однако учтите: каждый русский символ в UTF-8 занимает 2 байта, из-за чего длина Base64-строки растет быстрее. Для рекламы в Telegram настоятельно рекомендуется использовать короткую латиницу (например, c=direct_msk вместо c=директ_москва).
